# ⚡ Codex Fix

Автоматическая диагностика и исправление **сетевого окружения Codex на Linux**:
CLI, расширение в VS Code и отдельное приложение ChatGPT/Codex.

Один запуск проверяет доступность сервисов, находит рабочий локальный HTTP/SOCKS-прокси
или прямое соединение, исправляет только нужные способы запуска и проверяет результат.
Если проверенные маршруты и файлы исправны, повторной записи нет.

> Это сетевой помощник, а не универсальный ремонт приложения. Он не восстанавливает
> подписку, не обходит ограничения аккаунта и не вводит за пользователя данные входа.

## Быстрый старт

Нужны Linux, Bash, **Python 3.9+**, `curl` и стандартный `readlink`.
Для автоматического обнаружения портов нужен `ss` из пакета `iproute2`.

```bash
git clone https://github.com/TheLarrryLoveMom/codex-fix.git
cd codex-fix
./codex-fix.sh --fix
```

Репозиторий приватный: клонирование требует доступа к нему и настроенной авторизации GitHub.
Запускайте скрипт **от своего пользователя, без sudo**. VPN/прокси-клиент должен быть
установлен и подключён заранее, если прямое соединение не работает.

`--fix` автоматически проверяет все найденные компоненты и применяет необходимые
сетевые исправления. Исправные компоненты пропускаются. Запуск без параметров
сохраняет то же поведение. `--fix` нельзя сочетать с `--check`, `--dry-run` или `--restore`.

Диагностика без изменений:

```bash
./codex-fix.sh --check
```

Если автоматический поиск не нашёл ваш порт:

```bash
./codex-fix.sh --proxy http://127.0.0.1:10809
./codex-fix.sh --proxy 'socks5h://[::1]:1080'
```

`--proxy` задаёт предпочтительный маршрут для нуждающихся в исправлении компонентов.
Работающие компоненты принудительно на него не переключаются.

Для удобного запуска из любой папки можно создать ссылку, сохранив оба файла проекта рядом:

```bash
mkdir -p ~/.local/bin
ln -s "$PWD/codex-fix.sh" ~/.local/bin/codex-fix
```

Если `~/.local/bin` есть в `PATH`, используйте `codex-fix`. Не копируйте один
`codex-fix.sh` без `codex_fix.py`: проверяющая логика находится в Python-модуле.

## Как работает автоматическое исправление

1. Находит установленные команды `codex`, `code`, `code-insiders`, `chatgpt`,
   `codex-desktop`, стандартные каталоги расширения `openai.chatgpt` и desktop-ярлыки.
2. Проверяет три сервиса: OAuth OpenAI, API OpenAI и backend Codex в ChatGPT.
   Запросы не содержат API-ключей, токенов и пользовательских сообщений.
3. Проверяет текущее/ранее сохранённое окружение отдельно для CLI и GUI.
   Для GUI учитывает окружение доступного процесса GNOME Shell, Plasma или Cinnamon.
   Если его прочитать нельзя, проверяет прямое соединение.
4. При проблеме пробует заданный прокси, подходящее текущее окружение,
   сохранённые маршруты, прямой доступ, затем обнаруженные локальные прокси.
5. Повторно проверяет выбранный новый маршрут и создаёт адресные исправления.
   Уже исправные компоненты остаются без изменений.
6. Сверяет записанные файлы с ожидаемым содержимым. Повторный запуск проверяет сеть
   и управляемые файлы; при совпадении не переписывает их и резервные копии.

HTTP проверяется раньше SOCKS. Обнаружение использует TCP-порты известных
клиентов — INCY, Sing-box, Xray, Nekoray, Hiddify, Clash, Mihomo и других —
и распространённые локальные proxy-порты. Поддерживаются IPv4 и IPv6 loopback.

Прямой режим подходит и для TUN/VPN: наличие интерфейса с определённым именем
не требуется. В этом режиме proxy-переменные **удаляются** из окружения запуска;
значение `DIRECT_TUN` больше нигде не используется.

## Что исправляется для каждого приложения

| Компонент | Автоматическое исправление |
| --- | --- |
| Codex CLI | Пользовательская обёртка задаёт проверенное окружение и передаёт все аргументы исходной команде. |
| VS Code / Insiders | Обёртка запуска редактора передаёт proxy-переменные дочерним процессам, включая Codex, и сетевой флаг Electron. |
| Расширение Codex | Проверяется наличие в стандартных каталогах. Используется штатный бинарник расширения; `chatgpt.cliExecutable` не подменяется. |
| ChatGPT / Codex Desktop | Обёртка запуска задаёт окружение для приложения и его дочерних процессов. |
| Запуск из меню / URL-обработчик | Создаётся пользовательская копия существующего `.desktop` с тем же ID; сохраняются аргументы, `%F`/`%U`, действия и остальные поля. |

В `~/.bashrc` и `~/.zshrc` добавляется только выделенный блок функций
для исправляемых команд. Глобальные proxy-переменные для всех программ не устанавливаются.
Из прежней версии автоматически мигрируется только алиас рядом с её точным
маркером `AUTO-GENERATED BY CODEX DOCTOR`. Произвольные пользовательские
алиасы и функции не удаляются: при конфликте выводится сообщение и путь к обёртке.

После исправления откройте новый терминал. Для уже открытого VS Code или
ChatGPT/Codex сохраните работу, **полностью закройте приложение и откройте снова**.
Параметры запуска нельзя задним числом применить к уже работающему процессу.
Скрипт сообщает об обнаруженном старом окружении, но не закрывает ваши окна и сессии.

Если редактор или приложение отсутствует, скрипт сообщает об этом и проверяет найденные
компоненты. Он не устанавливает программы или расширения самостоятельно.

## Какие проверки считаются успешными

Ожидаемые ответы на запросы **без авторизации**:

| Сервис | Запрос | Ожидаемый ответ |
| --- | --- | --- |
| Авторизация | `HEAD https://auth.openai.com/oauth/token` | `405`, JSON |
| API | `GET https://api.openai.com/v1/models` | `401`, JSON |
| Codex backend | `GET https://chatgpt.com/backend-api/codex/models?client_version=0.0.0` | `401`, JSON |

Это ожидаемые отказы неавторизованному клиенту, подтверждающие доступность маршрута.
Скрипт проверяет итоговый HTTP-код и тип содержимого; промежуточный
`200 Connection established`, HTML-страница, `403`, ошибки TLS и тайм-ауты успехом не считаются.
Проверка использует системное доверие TLS и отключает чтение пользовательского `.curlrc`.

Успешная проверка **не доказывает**, что вход выполнен, квоты достаточно, WebSocket
и генерация ответа работают. Скрипт не читает `auth.json`, не отправляет платные запросы
и не выводит значения proxy-переменных из процессов.

Изменение поведения этих публичных endpoint-ов может потребовать обновления проверки.
Корпоративные, региональные или Cloudflare-ограничения могут оставить все маршруты
неподходящими. В этом случае скрипт завершится до записи изменений.

## Файлы, резервные копии и откат

Исправления хранятся в домашней папке:

```text
~/.local/share/codex-fix/
├── bin/                 # обёртки только исправленных способов запуска
└── manifest.json        # исходные версии файлов, контрольные суммы, маршруты

~/.local/share/applications/*.desktop  # пользовательские ярлыки
~/.bashrc / ~/.zshrc                   # небольшой managed-блок
```

`manifest.json` имеет права `0600`, обёртки — `0700`. Оригинальные версии файлов
хранятся в manifest в Base64: это кодировка, **не шифрование**. Не публикуйте этот файл:
в резервных копиях shell-конфигурации могут быть личные настройки.
Исходная копия не затирается последующими исправлениями.

Каждый файл заменяется атомарно. При обнаруженной ошибке записи уже выполненные
изменения текущей операции откатываются. Это не общая файловая транзакция:
аварийное выключение питания может прервать операцию.

Предпросмотр отката:

```bash
./codex-fix.sh --restore --check
```

Восстановление исходных файлов и удаление созданных инструментом файлов:

```bash
./codex-fix.sh --restore
```

Если после исправления вы отредактировали управляемый файл, перезапись или откат
останавливаются с сообщением о конфликте. Изменения пользователя нужно согласовать вручную.
Символические ссылки и пути за пределами домашней папки не перезаписываются.

## Параметры и коды завершения

| Параметр | Назначение |
| --- | --- |
| без параметров | Проверка и необходимые исправления без диалогов |
| `--fix` | Явный запуск автоматической проверки и исправления всех найденных компонентов |
| `--check`, `--dry-run` | Диагностика и план без изменения файлов |
| `--proxy URL` | Предпочтительный локальный HTTP, HTTPS, SOCKS5 или SOCKS5h прокси |
| `--timeout 1..30` | Тайм-аут запроса в секундах; по умолчанию 6 |
| `--restore` | Возврат к состоянию до первого исправления |
| `--version`, `--help` | Версия и справка |

Диагностика ограничена приблизительно 90 секундами плюс текущая группа запросов.
При большом числе портов задайте `--proxy`.

| Код | Значение |
| --- | --- |
| `0` | Проверки/исправления выполнены либо откат завершён; GUI может требовать перезапуска |
| `1` | Компоненты не найдены или есть пропущенные компоненты/конфликты |
| `2` | Ошибка аргументов, зависимостей, записи или отсутствие рабочего маршрута |
| `3` | `--check` обнаружил необходимые изменения |
| `130` | Проверка прервана пользователем |

## Границы поддержки

- Поддерживаются локальные Linux-установки и стандартные пользовательские каталоги.
  Windows, macOS, WSL/SSH Remote extension host, нестандартный `XDG_DATA_HOME`,
  профили с переопределёнными сетевыми настройками и sandbox-установки
  Snap/Flatpak требуют отдельной адаптации.
- AppImage распознаётся при наличии обычного desktop-ярлыка с прямым путём.
  Браузерные PWA не считаются нативным приложением Codex.
- Собственный `http.proxy` в настройках VS Code, workspace-переопределения,
  PAC-файлы и нестандартные launchers могут перекрывать окружение. Скрипт не правит
  произвольный JSONC и не считает сетевой тест проверкой всей конфигурации IDE.
- Для автоматического сохранения допускаются локальные proxy-URL без логина/пароля.
  Работающее существующее окружение с другим прокси можно проверить,
  но его секреты не копируются в обёртки.
- Сертификаты, настройки sandbox, модель, разрешения Codex, история и токены
  не изменяются. TLS-проверка не отключается.
- Процессы не завершаются, OAuth-порт не освобождается принудительно,
  системные пакеты и VPN-клиенты не устанавливаются.

Настройка запуска вместо подмены бинарника расширения выбрана с учётом
[официальной документации настроек Codex](https://learn.chatgpt.com/docs/developer-settings?surface=ide):
`chatgpt.cliExecutable` предназначен для разработки и может нарушать работу расширения.

## Разработка и тесты

```bash
bash -n codex-fix.sh
python3 -m unittest discover -s tests -v
shellcheck codex-fix.sh
```

Тесты выполняются офлайн, в отдельных временных каталогах, с подменой сетевой диагностики
и обнаружения программ. Они покрывают неизменяющий запуск, повторное применение,
разделение CLI/GUI, прямой режим, HTTP/SOCKS и IPv6, сохранение аргументов,
desktop-действия, резервные копии, ошибки записи, откат и конфликты ручных изменений.
GitHub Actions запускает проверки при push и pull request.

```text
codex-fix.sh              # точка входа
codex_fix.py              # диагностика, исправления, резервные копии
tests/test_codex_fix.py   # офлайн-регрессионные тесты
.github/workflows/check.yml
README.md
```
